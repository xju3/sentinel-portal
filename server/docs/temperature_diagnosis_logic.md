# 工业设备温度诊断算法逻辑备忘录 (Temperature Diagnosis Logic Memo)

## 1. 核心设计理念
区别于传统的“死守绝对高温阈值”策略，本套温度诊断架构采用了**极速短路优化 (Fast-Fail)**、**动态比例报警 (Ratio-Based Alarming)** 以及 **同组空间差分 (Peer Validation)** 相结合的立体诊断模型。

旨在解决工业现场最典型的三大痛点：
1. **环境昼夜温差干扰**：夏天中午厂房整体升温导致的群体误报。
2. **传感器接触热阻**：绝对温度传导滞后导致的严重漏报。
3. **传感器 ADC 读数微小跳动**：非完美单调递增导致的代码逻辑失效。

---

## 2. 诊断分级体系 (Severity Levels)
本系统所有的状态分级均映射到一套通用的 5 级整数编码体系，与前端 UI 颜色及报警规则引擎强绑定：
*   `0`: **正常 (Normal)**
*   `1`: **关注 (Attention)**
*   `2`: **异常 (Abnormal)**
*   `3`: **报警 (Warning)**
*   `4`: **危险 (Critical)**

---

## 3. 算法执行主流程

### Phase 1: 极速短路优化 (50% Short-Circuit Rule)
*   **输入**：当前物理温度 `current_temp`，设备绝对极限阈值 `max_absolute` (如 85℃)。
*   **逻辑**：计算当前温升比例 `Ratio = current_temp / max_absolute`。
*   **动作**：如果 `Ratio < 50%`，说明机器处于绝对安全和低温状态。算法**立即阻断并返回 `0: 正常`**。
*   **价值**：跳过所有复杂的 Redis 查库和斜率计算，为常年健康运行的 90% 以上设备节省海量服务器算力。

### Phase 2: 空间维度横向校验 (Spatial Peer Validation)
如果 `Ratio >= 50%`，说明设备在发热，开始介入深度诊断。
*   **消除共模干扰**：从 `DeviceContext` 查出同车间/同工艺的 `peer_group`（兄弟设备）。
*   **计算环境基线**：去 Redis ZSET 中查询所有兄弟设备的当前温度，取其**中位数 (`peer_median`)** 作为当前的环境热背景。
*   **计算净增温**：`Effective Rise = current_temp - peer_median`。
    *   *案例*：如果当前机器涨了 10度，兄弟机器也涨了 10度（夏天中午），净增温为 0。完美滤除环境干扰。

### Phase 3: 多级动态比例报警 (Ratio-Based Alarming)
依据当前所处的绝对危险边缘比例，进行基础定级：
*   `Ratio > 50%`：判定为 **`1: 关注`** (设备热身，进入观察区)。
*   `Ratio > 70%`：判定为 **`2: 异常`** (安全裕度缩小，需列入维保计划)。
*   `Ratio > 80%`：判定为 **`3: 报警`** (严重发热，极度接近临界值)。
*   `Ratio > 90%`：判定为 **`4: 危险`** (濒临毁灭性故障边界，随时抱死起火)。

### Phase 4: 数学级线性回归防抖 (Noise-Resilient Linear Regression)
如果设备处于 `1: 关注` 或 `2: 异常` 状态，算法需要检查其**恶化速度**。
*   **摒弃单调递增**：现场风吹草动会导致读数微小回踩 (`60.1 -> 62.5 -> 62.2`)。严苛的连续 `a < b < c` 逻辑会导致 100% 漏报。
*   **最小二乘法拟合**：从 Redis 极速拉取该测点过去 N 个周期的所有时间序列数据。使用线性回归算出其真实的**数学拟合斜率 (Slope, ℃/小时)**。
*   **越级上报**：即使目前比例只有 60%（关注级），但如果拟合出的斜率大于 15℃/小时（急速飙升），系统将人工介入，强行将等级提升至 **`3: 报警`**，在灾难发生前拦截故障。

---

## 4. 数据落库 (Persistence)
最终算法产出的所有结论与中间证据，均打入全新设计的 `diagnosis` 与 `diagnosis_item` 表中：
*   由 `sensor_sn` 驱动彻底转为 `device_id + location_id` 的拓扑驱动。
*   在 `diagnosis_item` 中，不仅存入计算出的 `level` (0~4)，还将上述的 `Ratio`, `Effective Rise`, `Slope` 等核心参数打包以 JSON 形式存入 **`evidence`** 字段，供前台诊断专家追踪溯源。
