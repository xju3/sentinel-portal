# 设备振动健康基线构建策略 (Baseline Strategy)

## 1. 核心挑战与业务痛点
旋转机械在运转周期内，由于物理磨损（如轴承滚道微观粗糙度增加、润滑脂消耗），其绝对振动值并非固定常数，而是会随着时间的推移呈现极为缓慢的抬升趋势。
如果采用固定的绝对阈值（如 ISO 10816 刚性基础 4.5 mm/s），极易发生：
1. **漏报**：对早期微弱故障（如局部微小点蚀）的能量抬升极度迟钝。
2. **误报**：当设备正常服役至中后期，即使无严重缺陷，整体振动也会逼近固定红线，导致告警泛滥。

因此，必须构建随设备衰老而“动态平滑抬升”的健康基线，用于计算相对偏离幅度。

## 2. 统计算法：中位数 (Median)
基线的核心统计算法采用滑动窗口内的 **中位数 (50th Percentile)**，而非平均数 (Mean / EMA)。

### 2.1 中位数的不可替代性 (抗崩溃特性)
* **移动平均 (EMA) 的缺陷**：容易被异常毛刺严重污染。若发生持续几小时的真实故障导致振动飙升，平均值会被大幅拉高，从而掩盖故障，导致漏报。
* **中位数的绝对免疫力**：中位数的统计学“崩溃点”为 50%。只要滑动窗口内，超过半数的采集样本是正常稳态运行数据，即使剩余的 49% 全部是极端高能冲击，中位数也坚如磐石，毫不偏移。这确保了基线只会锚定设备概率密度函数 (PDF) 中最集中的健康底色。

## 3. 滑动窗口选择：为什么是 7 天？
在计算基线时，滑动窗口的时间长度选择极其关键，它决定了基线的平滑度与适应滞后性。

### 3.1 每天构建 (1 天窗口) 的缺陷
1. **故障掩蔽 (Fault Masking)**：崩溃阈值仅为 12 小时。若设备出现长达十几个小时的异常振动，次日基线就会被立刻拉高，将“异常”合法化。跟随速度过快，导致永远不报警。
2. **变工况震荡**：若设备当日仅短暂运行或长期重载，样本量极小且偏置，基线会产生剧烈震荡。

### 3.2 每周构建 (7 天窗口) 的优势
1. **充足的干预周期**：崩溃阈值为 3.5 天。异常必须连续存在长达 3.5 天才会拉升基线，这为预测性维护 (PdM) 留出了充足的专家诊断与维修窗口。
2. **滤除操作杂音**：长周期的宏观统计能充分吸收并平滑设备每天在不同负载、不同启停状态下的物理波动。
3. **真实磨损跟踪**：7 天步长既能容忍正常物理老化导致的缓慢抬升，又能敏锐地暴露突发的高频加速退化。

## 4. 生命周期管理
1. **冷启动 (Cold Start)**：新设备或基线被重置后，前 7 天无完整基线数据。此时基线默认判定为 `0.0`（完全依赖固定报警红线与突变率）。
2. **周期性滚动 (Rolling Update)**：后台批处理任务每 7 天拉取 InfluxDB 中过去一周的有效运行数据，清洗极低值后，计算中位数并持久化入库，旧基线标记退休。
3. **强制重置 (Manual Reset)**：设备经历大修（如更换轴承）后，振动状态发生突变下降。维修人员手动一键重置，强制作废当前基线，重新进入冷启动自学习期。
