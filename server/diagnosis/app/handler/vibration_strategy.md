# 振动复采与 FFT 任务策略

本文档描述当前服务器实际采用的任务职责、发出时机和去重规则。设备任务协议保持：

- `action=53, val=3`：每 5 分钟复采一次完整检测数据，共 3 次。
- `action=99, val=0`：设备立即进行 FFT；点数和量程由固件决定。

## 1. 职责边界

`/sensors/data` 请求内的快速决策负责让任务随当前 HTTP 响应返回。诊断进程不再直接构造任务记录，而是通过统一的任务服务申请任务：

- 快速决策：负责温度/振动分流、首次复采、最终复采后的即时 FFT，以及每日 FFT。
- 任务服务：负责任务持久化、并发去重、任务用途和复采后续 FFT 的关联。
- 深度诊断：负责完整诊断、告警和诊断案例；当其发现快速规则未覆盖的振动异常时，通过任务服务补建复采或最终 FFT，作为安全兜底。

快速决策失败时，接口返回 `503`，要求设备重传本次数据，避免上传成功但任务决定被静默丢弃。

## 2. 温度与振动分流

温度变化通常是缓慢过程：

- 温度不触发 `action=53`。
- 温度不触发异常 FFT。
- 温度诊断与告警继续由深度诊断处理。

振动快速判断当前包含：

- RMS 绝对值或相对上次常规数据的快速变化。
- 三轴任一轴时域峭度超过早期冲击阈值。

峭度用于补充“早期轴承故障尚无明显 RMS 抬升”的场景。它只表示需要复核，不能单独确诊轴承故障。

## 3. 异常任务时序

```text
常规数据上传
  └─ 无振动快速异常 → 检查每日 FFT
  └─ 有振动快速异常 → 当前响应返回 action=53
                            │
                            ├─ 第 1、2 次复采：只记录，不发 FFT
                            │
                            └─ 第 3 次复采
                                  ├─ 已恢复正常：结束，不发 FFT
                                  └─ 仍异常：同一响应返回 action=99
```

复采任务与其后续 FFT 使用持久化关联。最终复采重复上传时：

- 若 FFT 已下发但未完成，服务器返回同一个 FFT 任务，不创建新任务。
- 若 FFT 已完成，服务器不再创建第二个 FFT。

深度诊断若在最终复采中确认 `vib_level >= 2`，会复用相同的后续关联；它不会与快速决策生成两条 FFT。

若深度诊断在常规数据中发现快速规则未覆盖的 `vib_level >= 2`，统一任务服务会建立一条复采任务。由于深度诊断运行在原 HTTP 响应之后，这条兜底任务只能在设备下次上传时返回；这是当前架构中唯一允许存在的诊断周期延迟，主快速路径不受此延迟影响。

## 4. 每日健康 FFT

设备每 24 小时至少成功完成一次 FFT：

- 只在常规、无快速振动异常的数据上传请求中检查是否到期。
- 最近 24 小时已有成功完成的任意 FFT，则本次不再创建每日任务。
- 有复采任务正在执行时，不插入每日 FFT。
- 到期且无冲突时，在当前响应直接返回 `action=99`。
- 不做历史欠账补发；设备离线多天后只发一条。

每日 FFT 与异常 FFT 使用相同设备命令，但数据库用途分别记录为 `FFT_DAILY` 和 `FFT_DIAGNOSIS`。异常确认可以复用尚未完成的每日 FFT；任务用途随之提升为诊断 FFT。

## 5. FFT 分析能力边界

当前 v1 FFT 文件上传的是三轴幅值频谱，不含原始时域波形和相位。因此服务器当前可以：

- 保存并绘制三轴幅值频谱。
- 在已配置转速时标注 1X、2X、3X，给出通用频谱筛查结果。
- 将高于 3X 的主峰描述为“高频激励”，供用户判断。

配置了轴承型号并与设备规格的安装位置绑定后，服务器还会计算并绘制 BPFO、BPFI、BSF、FTF 参考标线，提示主峰是否落在特征频率邻域。该提示仍属于幅值频谱筛查。

当前不能可靠执行：

- 从 FFT 幅值频谱反推时域峭度。
- 包络解调或包络谱分析。
- 仅凭一次频率邻近匹配确诊轴承故障或判断严重度。

所以没有轴承参数的设备只提供通用频谱图和有限筛查，不宣称轴承故障；已有轴承参数的设备增加特征频率参考和“疑似吻合”提示，但仍需扩展上传协议，使其包含原始时域数据，才能真正进行包络分析。

## 6. 轴承配置与后续演进

当前服务器已经提供：

- 租户级轴承型号目录，维护滚动体数量、滚动体直径、节圆直径和接触角。
- `device_spec` 到多个安装位置的轴承绑定，以及内外圈转速比例。
- 结合设备规格转速计算 BPFO、BPFI、BSF、FTF。
- 绑定或参数变化后的诊断上下文缓存失效。

后续仍需补充原始时域波形或设备端包络谱协议，并使用采样时实际转速替代配置转速。

在这些条件具备前，系统保持“通用频谱筛查”措辞，避免把高频峰值误报为轴承故障。
